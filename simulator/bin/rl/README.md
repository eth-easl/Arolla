# `bin/rl/` — RL entry points

This folder is **the only place the RL extension is "activated"**. The core
simulator (`bin/workflow.py`, etc.) is unchanged and runs static scenarios as
before. The scripts here wrap the same engine in a Gymnasium loop that adjusts a
retry budget online.

The final/report model is named **DIRB** in the report, for **Dynamic Istio Retry
Budget**. In this repository, the committed DIRB checkpoint is
`models/RB-RL.v5/`.

Run everything from the `simulator/` directory.

## Layout

```text
bin/rl/
  _pathsetup.py     # puts src/ + sibling script folders on sys.path (imported by every script)
  rl_paths.py       # shared rule for WHERE eval/benchmark output is written
  matplotlib_safe.py# headless matplotlib config shared by plotting scripts
  train/            # train a policy  -> trained_models/<family>/run_*/
  eval/             # run a saved policy on one scenario + plot
  benchmark/        # RL vs no-budget / static / best-static suites
  analyze/          # inspect which telemetry signals the policy uses
```

## How to read this folder

Think of `bin/rl/` as the command-line interface for the RL work. The actual RL
environments live in `src/simulator/rl/`, the scenario inputs live in
`experiments/yaml/rl/`, and trained/reference models live in `trained_models/`
or `models/`. The scripts here connect those pieces together.

| Directory / file | What it serves | What is inside | Use it when |
|------------------|----------------|----------------|-------------|
| `train/` | Create a new PPO policy from simulator rollouts. | One trainer per model family, plus smoke-test trainers. | You want to produce a new checkpoint under `trained_models/`. |
| `eval/` | Run one saved model on one YAML scenario. | Evaluation scripts that compare RL against no-budget/static baselines and usually make one plot. | You want a quick sanity check or visual rollout. |
| `benchmark/` | Run a saved model across a suite of stress scenarios. | Suite runners, scenario resolvers, and baseline-search helpers. | You want CSVs that compare policies across faults. |
| `analyze/` | Explain what a trained policy learned. | Signal-importance, first-layer-weight, rollout-correlation, and plotting helpers. | You want to justify why the model acts the way it does. |
| `_pathsetup.py` | Keeps direct script execution reliable after the folder reorganization. | Adds `src/` and all RL sibling script folders to `sys.path`. | Imported by scripts; you normally do not run it. |
| `rl_paths.py` | Keeps generated outputs out of tracked model folders. | Shared default-output-directory rules for eval/benchmark scripts. | Imported by scripts; use it if adding a new output-producing script. |
| `matplotlib_safe.py` | Makes plotting work on headless machines/CI. | Matplotlib backend/cache setup. | Imported before scripts create plots. |

The normal workflow is: **train** a model, **eval** it on one scenario, then
**benchmark** it across the full suite, and optionally **analyze** the learned
signals.

Each subfolder has its own `README.md` describing every script in it. For *what
each model is and its reward function*, see
[`../../docs/rl/models.md`](../../docs/rl/models.md). The top-level guide is
[`../../docs/rl/README.md`](../../docs/rl/README.md).

## Output conventions (where everything goes)

The aim is that **nothing generated by these scripts ever pollutes version
control or the committed reference model**. Three rules cover all of it:

| What | Written to | Tracked by git? |
|------|-----------|-----------------|
| **Training runs** (`train/`) | `trained_models/<family>/run_<timestamp>_<steps>/` | No (`trained_models/` is git-ignored) |
| **Eval / benchmark on your own run** | next to the model, inside its `trained_models/...` run dir | No (same git-ignored tree) |
| **Eval / benchmark on the committed model** (`models/RB-RL.v5/`) | redirected to `outputs/rl/<suite>/<model_name>/` | No (`outputs/` is git-ignored) |
| **Smoke tests** (`train_rl_test.py`, `train_random_test.py`) | `trained_models/_smoke/` | No |

The redirect for the committed model is handled by `rl_paths.default_output_dir`,
so you never accidentally `git add` a benchmark PNG into `models/`. You can always
override the location with `--output-dir` (benchmarks) or `--output` (eval).

A training run directory contains:

```text
run_<ts>_<steps>/
  model.zip                 # the PPO policy
  vecnormalize_stats.pkl    # REQUIRED for inference (obs/reward normalization)
  best_model/               # best checkpoint found during eval callbacks
  eval_logs/                # SB3 evaluation logs
  tb_logs/                  # TensorBoard logs
  plots/                    # training/eval plots
  training_spec.txt         # exact hyperparameters + spaces used
  model_variant.txt         # which env/action variant produced this model
```

## The one rule for inference

A saved model is only valid together with **its own** `vecnormalize_stats.pkl`
and the **same** decision/observation/delta windows it was trained with. The eval
and benchmark scripts load the stats automatically when you pass
`--model <dir>/model` (no `.zip`). For `RB-RL.v5` the windows are `5 / 10 / 5`.
